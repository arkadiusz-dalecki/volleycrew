## E2 access parameters - approved 2026-11-06

User approved: session expires after 30 days without use, no later than 180 days from creation; the PIN reset grant is one-time and valid for 30 minutes; after 5 failed profile PINs in a 15-minute window, subsequent attempts are temporarily rejected until the end of this window. There is no permanent block due to incorrect PINs. Correct logging in before the limit is reached resets the profile counter. After the window has expired, you can try again. Separate technical source protection: 30 failed PINs/15 minutes; registration/bootstrap/reset: 10 attempts of the given operation/source/15 minutes. Counters are persistent in PostgreSQL. Trusting proxy headers requires explicit configuration; tunnel configuration and ingress test remain E10.

## D8 closure in E8 - approved 2026-11-07

The user approved an expectation scale of 400 with K=32. For average ratings of 1000 versus 1200, the weaker players receive +24.3 for 5:0, +11.5 for 3:2, and +8.3 for a draw; stronger players lose 5.1 points if they win only 3:2. The result is judged against expectations, not just the victory itself.

Allowing full correction of historical actual attendance and lineups in one operation with mandatory reason, keeping previous versions and recalculating this and subsequent fixtures. Reasons for attendance corrections are still available only to the organizer and the player concerned.

Matches are counted according to the starting time, and if the starting time is identical, according to the permanent match ID. The order in which the results are entered does not matter; adding an older result recalculates subsequent matches. Correction does not change the start time of the match; stable replay order does not depend on the revision number or the time it was saved.

## Bundled database - approved 2026-11-08

The user does not have PostgreSQL and requested a database bundled with Volleycrew. This replaces the previous requirement for a separate server for new installations (D1/E0/E10). The 0.2.0 package includes PostgreSQL 17, a persistent /data/postgresql directory, an automatically created database/role/password, and a private loopback listener. DATABASE_MODE=auto selects the bundled database when POSTGRES_HOST is empty; the existing host retains external mode. Changing a persisted mode requires explicit data migration, without automatically creating an empty alternative. HA backup stops the application and copies the consistent cluster; Additionally, logical backup and restoration from the archive works when cluster files are missing. There is no automatic upgrade to the major version of PostgreSQL.
