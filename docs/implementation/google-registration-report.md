# E2/E9 - Google registration with editable data

Date: 2026-11-15. Order: invitation from the organizer → Join via Google → suggested name/surname with the option to change → approval and an account without a password. Complements open PR #11. Without deployment or reading/changing production data.

## Contract and migration

New register mode (invite_token) and password in Google start, basic openid/profile scope. JWT, PKCE, nonce, issuer/aud/exp and the one-time browser-bound state are still implemented by the current Authlib/PyJWT provider; hints are only read from the token after correct verification. In Google's description, profile fields are optional and therefore not an identifier.

New endpoints: POST /auth/google/completion {token}, POST /auth/google/register {token, first_name, last_name, nickname?}, POST /me/google/password {token, username, password}. Your own account's DTO contains has_password and nullable username. Thin routes delegate finalization to google_actions; OAuth flow stays in google_auth and shared sessions/CSRF in auth/security.

Migration **0013_google_registration** adds invite mode/context in GoogleFlow and GoogleActionGrant table. Profiles without legacy PIN migration data do not retroactively gain Google-only access: their old associations/sessions are invalidated before the new path is triggered. Bootstrap remains closed to the organizer having any access method. Names, enrollments, attendance, teams, history and ELO remain. Downgrade does not provide Google-only access in legacy code; use a compatible backup/image for rollback. Version 0.3.4 unchanged (no bump request).

## Local verification

macOS arm64, Python 3.13.18, PostgreSQL 17.11, Node 26.8.1. Backend: separate volleycrew_google_join_test; browsers: volleycrew_google_join_e2e_test, loopback port 59643. One database is not reset by both sets at the same time.

- Full pytest on PostgreSQL: **207 passes**, 2 existing HTTPX warnings. Includes signed JWT and real Authlib exchange via Google Transport-only substituted, session/link boundaries, competition, migrations, rest application rights and rules.
- Dedicated Google E2E: **12 passes** (58.2 sec) in desktop/mobile/WebKit. It checks hints, name change, no account before approval, guest/no password after approval, logging in with the same sub, adding a password after new Google, disconnection and local login. Separately clearing the fragment and refreshing it. Tests respect actual Retry-After on clicks that are too fast; they do not disable or reset the application limiter.
- **11 unit frontend**, lint, types, OpenAPI generate/check and build passed. The mobile form screenshot was checked visually; screenshots remain outside the repository.
- Full regular E2E matrix: **83 passed, 1 intentionally skipped on desktop** (4.4 min). Actual amd64/aarch64, HTTPS/Ingress and backup/restore images: CI result for final HEAD in PR. Docker locally unavailable.
